# Contributing to Resonate

Thanks for looking. A few things are worth knowing before you spend time on a change.

## The one thing that surprises everyone

**Resonate does not run in Expo Go.** It reads tags off raw bytes, extracts embedded cover
art, plays audio in the background and drives native lock-screen controls — all of which
need native modules that Expo Go does not ship. You need a development build:

```sh
npm install
npx expo run:android   # or: npx expo run:ios
```

That first build takes a while. After it, `npx expo start` is enough.

You also need **audio files on the device**. On Android the scan finds whatever MediaStore
already indexed. On iOS there is no such thing — drop files into the Resonate folder in the
Files app, or use *Import files…* in onboarding. Files with real tags and embedded art
exercise far more of the code than a folder of untagged MP3s.

## Before you open a pull request

```sh
npm run check   # typecheck + lint + tests
```

All three have to pass. They run in about a minute and need no emulator.

- **Node 22.18 or newer.** The tests run `.ts` straight through `node --test`, which needs
  the type stripping that landed in that version. On older Node you get
  `ERR_UNKNOWN_FILE_EXTENSION`.
- If you added or renamed a route, run `npx expo start` once before `npm run typecheck`:
  route types are generated by Metro into `.expo/types/`, and without that the check uses
  the old list.

## What the tests cover, and what they can't

There are no fixtures in the repository — every binary buffer is assembled inside the test.
That is deliberate: a checked-in FLAC is a file nobody can review.

The suite covers what is verifiable without a device and easy to break silently: the tag
reader across four formats, duration maths, the header window handed to it, the `.lrc`
parser, search, path portability, queue continuation, spoken-word classification, listening
sessions, the metadata-edit layer, colour maths and the translation dictionary.

It cannot cover playback, permissions, MediaStore, or anything that touches a real file
system. If your change lands in that territory, say in the pull request **what you ran it
on** — which platform, which device or simulator, which files. "Tested on a Pixel 7 with a
folder of tagged FLACs" is worth more than any number of green checks.

## House style

The code is commented in **Portuguese**, and so are `docs/`. The interface is translated
into five languages. Please match whatever file you are in rather than switching.

A few conventions that are load-bearing:

- **Comments say why, not what.** Most comments in this codebase name a decision and its
  cost. If a line looks odd and it isn't, that is exactly where a comment belongs.
- **`ponytail:` marks a deliberate shortcut**, at the exact spot, naming the ceiling and
  the way out. `grep -rn "ponytail:" src/`. Adding one is fine — leaving a shortcut
  unmarked is not.
- **No user-facing string in a component.** Every one goes through `t('key')` and the
  dictionary in `src/lib/i18n.ts`, with all five languages filled in. The `satisfies` at
  the bottom of that file rejects a missing translation at compile time; a string typed
  straight into JSX slips past it and ships in the wrong language.
- **Nothing absolute goes to disk.** Track ids and stored paths are portable references —
  see `src/lib/paths.ts` and the comment at the top of it. Writing a raw `file://` into a
  JSON is how the library breaks on the next iOS reinstall.
- **Pure logic lives in `src/lib` and gets a test.** If a decision is worth getting right,
  it should be reachable from `node --test` — which in practice means it must not import
  `expo-file-system`.

## Design

The visual source of truth is the HTML prototype in
`Offline Music Player App-handoff/…/Resonate - Offline Player.dc.html`. Typography,
spacing and colour come from its inline styles, collected in `src/constants/theme.ts`.
Please take values from there rather than inventing new ones.

Resonate is **dark only**. That is a product decision, not a missing feature.

## Reporting a bug

The most useful reports say which platform, which file formats, and what the tags looked
like. If the scan found the wrong thing, the filename and the output of any tag editor on
that file is usually enough to reproduce it — please don't attach the audio itself.
